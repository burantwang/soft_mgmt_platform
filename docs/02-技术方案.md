- 无物理外键，业务代码保证关联；高频筛选字段建索引；状态/类型字段对应 Java 枚举。

## 七、核心业务规则实现要点

1. **报告解析**（sonic/util/HtmlReportParser）：格式校验（存在 `table#environment` 与 `table#results-table` 且含 pytest-html 标记）→ 提取 Environment(Project→机型/Branch/Version) → 解析 Summary 统计 → 提取 failed/error 用例 col-name + log → 判定失败。
2. **上传流程**：upload 仅解析返回预览 → 前端确认 → POST /api/sonic/releases 入库；Jenkins 推送直接解析入库。
3. **任务流转**：失败自动建任务+明细 → 管理员指派 → 责任人填写更新 → 状态流转。
4. **数据级权限**：明细更新接口校验"当前用户=责任人"或拥有 sonic:edit。
5. **XSS 双防线**：后端 jsoup 白名单（入库前）+ 前端 DOMPurify（渲染前）。
6. **文件存储**：相对路径入库，绝对路径来自环境变量 `FILE_STORAGE_ROOT`；下载校验相对路径防穿越。

## 八、部署与多环境

- docker-compose：mysql（挂载 `sql/init.sql` 自动初始化）+ backend + frontend(nginx 反代 `/api`)。
- 镜像不打包配置，全部环境变量注入。
- 环境变量：DB_URL/DB_USER/DB_PASSWORD、FILE_STORAGE_ROOT、API_PUSH_TOKEN、SA_TOKEN_SECRET、ADMIN_INIT_PASSWORD、APP_ENV、MYSQL_ROOT_PASSWORD。
- 迁移：拷贝 compose+sql+产物 → 配置环境变量 → up -d → 验证。
