# 01 - 需求确认记录

> 本文件为项目需求基线，所有业务规则以本文件与《02-技术方案.md》为准。随需求变更同步更新。

## 一、项目定位

- 面向软件研发/测试团队日常业务的**模块化集成平台**（非单一工具）。
- 当前版本（V1）包含两个业务域：**Sonic 版本发布管理**、**Wiki 知识库（文档与文件）**。
- 平台结构、界面、权限、部署均**预留后续业务扩展能力**（详见 §五）。

| # | 确认项 | 结论 |
|---|--------|------|
| 1 | 平台定位 | 可扩展集成平台，Sonic 发布 + Wiki 为当前业务模块 |

| 21 | 文件资源 | 独立文件管理模块 + Wiki 文档可关联引用 |
| 22 | 文件白名单 | html / pdf / 图片 / office 文档 / 压缩包等常见类型；单文件 ≤ 50MB |
| 23 | 初始化账号 | SQL 预置角色与权限点；超管 `admin` 由后端初始化器创建（密码经环境变量注入，BCrypt 加密，首次登录强制改密） |

## 四、开发流程约定

固定流程：需求理解 → 提出疑问 → 输出完整技术方案 → 确认后拆解开发任务 → 分阶段编码实现。
**每阶段完成必须停下等待审核确认，禁止一次性输出全部代码。**

## 五、扩展性设计要点

- 后端：`common`/`config` 平台基座与业务域解耦；新域 = `module/` 下新建独立包 + 新权限点数据 + 新路由菜单。
- 前端：路由/API/组件按域拆分文件；菜单由路由 meta 动态生成；主布局零改动接入新模块。
- 权限：`sys_permission.module` 按模块挂载，动态角色勾选，天然支持新模块。
- 数据：枚举类字段（FileType/ReleaseSource 等）在 Java 枚举中追加新值即扩展；通用字段预留（remark/sort/status）。
